# 고이 개발 문서

README에서 덜어 낸 동작 상세, 데모·시뮬레이션 도구, 화면 설계, 구조, 검증 기록.

## 기능 상세

| 기능 | 동작 | 차량 데이터 · SDK |
|---|---|---|
| 픽업 장소 자동 제안 | 등록한 장소에 들어서면 맞는 모드를 음성으로 묻고 "응"으로 켠다 | FusedLocation 근접 알림, TTS, STT |
| 쏠림 감지 | 약 1초 차속 변화로 급제동·급출발, 조향각과 차속으로 급커브(a<sub>y</sub> ≈ v²·tan(δ/i)/L)를 모드 민감도 기준으로 판정한다. 한 번의 급제동은 한 번만 센다(기준 아래로 내려가야 다시 셈). 효과음 1회 + 기록, 주행마다 종류별 처음 한 번은 "급제동이에요"처럼 말로 알린다 | AAOS `PERF_VEHICLE_SPEED`, Vehicle SteeringWheel |
| 커브 사전 안내 | 내비 경로 앞 급커브(`TURN_SHARP_*`)·유턴이 설정한 거리(100·200·300m) 안에 들어오면 "앞에 커브가 있어요, 천천히" | NaviHelper `onTBTInfo` |
| 모드별 공조 | 냄새 빼기(외기 유입 + 바람 2단계), 실내 온도 낮추기(-2°C), 바람 줄이기, 뒷좌석 온도 유지, 직접 바람 피하기, 주기적 환기(10·20·30분). 모드를 모두 끄면 원래 값으로 돌린다. 아기·반려동물 항목은 기어 P가 아닐 때만 동작(신호 대기에는 유지). 쓸 수 없으면 "외기로 바꿔 보세요"라는 음성 권유로 대신한다 | Vehicle HVAC(capability 확인 후 쓰기) |
| 모드 겹침 | 여러 모드를 함께 켜면 가장 민감한 기준과 모든 공조 항목을 합친다 | — |
| 운반 요약 | 기어 P로 도착하면 무사히 왔을 때는 모드별 축하 문구 3개를 차례로, 흔들림이 있었으면 도착 사실만. 출발 장소·시간·거리, 급제동·급커브·커브 안내·급출발 횟수와 순서. "계속 켜 두기 / 모드 끄기" | Vehicle Gear, 차속 적분 |
| 하차(망각) 알림 | 도착 후 운전석 문이 열리면 트렁크·뒷좌석·컵홀더를 알린다. 트렁크는 모드별로 기억한다(픽업 때 트렁크를 연 모드만, 짐을 먼저 싣고 10분 안에 모드를 켜도 인정). 아기·반려동물은 확인 버튼을 눌러야 닫힌다 | Vehicle Door(`ROW_1_LEFT`, `REAR`) |
| 아기 수면 모드 | "아기 자요"로 켠다. 효과음을 끄고 안내 음성을 짧게, 화면을 어둡게. 감지한 일은 신호 대기 때 "수면 중 알림"으로 보여 주고 출발하면 닫는다. 도착(P)하면 꺼진다 | STT |
| 휴식 안내 | 반려동물 모드에서 정한 간격(1·2시간)마다 쉬어 가라고 말한다 | 주행 시간 |
| 챌린지 | 커피 한 방울도 안 흘리기, 케이크 무사 운반, 멀미 없는 드라이브, 국물 한 방울도 지키기, 깨우지 않고 도착. 운반 기록에서 계산한다 | 운반 기록 |
| 백그라운드 | 모드가 켜진 동안 포그라운드 서비스로 리스너를 유지하고, 화면 밖에서는 제안·알림을 시스템 알림으로 띄운다 | — |

Vehicle SDK 쓰기는 `check*Capabilities`로 WRITE를 확인한 영역에만 하고, 매니페스트에는 실제로 쓰는 퍼미션만 선언한다(`app/src/main/AndroidManifest.xml`). `MainActivity`는 `distractionOptimized`를 선언해 주행 규제 중에도 화면이 보인다. Pleos Connect SDK는 `settings.gradle.kts`에 등록한 Pleos Maven 저장소(`nexus-playground.pleos.ai`)에서 받는다.

## 데모와 시뮬레이션

에뮬레이터에서 시나리오를 반복 재현하는 도구 세 가지. 디버그 빌드에서만 쓴다.

| 도구 | 하는 일 | 결과 |
|---|---|---|
| 데모 주입(`DemoReceiver`) | adb 브로드캐스트로 차량 상태·장소 진입·발화를 앱 안에서만 바꿔 넣는다 | 즉시 |
| `scripts/drive-sim.sh` | 페르소나 시나리오를 앱 안 주입값으로 빠르게 재현한다(0.25초 간격으로 차속을 조금씩 바꿈) | `build/sim/<시나리오>/` 단계별 화면, `log.txt` |
| `scripts/road-test.sh` | 내비 경로 시뮬레이션이 차를 움직이고, 그 진행에 맞춰 시스템 차속·조향·기어(VHAL)와 GPS를 바꾸고, 대답은 마이크로 넣는다 | `build/road-test/<시나리오>/` 녹화·화면·확인 결과 |

### 데모 주입

값에 공백을 넣지 않는다. 시스템 차속·주행 규제는 바뀌지 않는다.

```sh
B="adb shell am broadcast -a dev.seungmin.goi.DEMO -p dev.seungmin.goi"
$B --es enter seed-bakery            # 달콤베이커리 진입 → 파손주의 모드 제안
$B --es say 응                       # 음성 응답 대신
$B --ez trunk true; $B --ez trunk false   # 픽업 때 트렁크 열고 닫기
$B --es gear D --ef speed 20          # 출발(차속 km/h)
$B --ef speed 50 --es curve SHARP_R:250  # 앞 250m 급커브 → 사전 안내
$B --ef speed 15                      # 1초 안에 50→15: 급제동
$B --ef speed 0; $B --es gear P       # 도착 → 운반 요약
$B --ez door true                     # 운전석 문 열림 → 하차 알림
$B --es say 아기자요                  # 수면 모드
$B --ei elapse 61                     # 주행 시간 61분 앞당김 → 반려동물 휴식 안내
$B --ez reset true                    # 주입값 해제
$B --es route "37.3947,127.1112,판교역" --es via "37.40403,127.10425,카페"   # 내비 경로 요청(경유지 선택)
$B --ez navtrace true                 # 내비 위치·TBT를 GoiNavTrace 로그로(모의주행 GPS 미러용)
$B --es place "seed-bakery,달콤베이커리,37.41146,127.09936,50,FRAGILE"     # 픽업 장소를 좌표로 등록
```

### 시나리오 반복 시뮬레이션

```sh
scripts/drive-sim.sh -c all        # -c: 앱 데이터를 지우고 기본 픽업 장소로 시작
scripts/drive-sim.sh baby          # 하나만
```

| 시나리오 | 흐름 |
|---|---|
| `cake` | 달콤베이커리 제안 → 트렁크 → 커브 사전 안내 → 급제동 → 치킨 드라이브스루에서 포장 음식 추가(겹침) → 도착 요약 → 하차 알림 |
| `baby` | 아기 모드 → "아기 자요" → 급제동(효과음 없이 기록) → 신호 대기에서 "수면 중 알림" → 출발하면 닫힘 → 도착 → 확인해야 닫히는 하차 확인 |
| `pet` | 반려동물 모드 → 급커브 → 61분 경과 휴식 안내 → 도착 |
| `coffee` | 드라이브스루 진입 중 음료 모드 제안 → 신호 출발 급출발 → 도착 → 컵홀더 알림 |

### 모의주행

환경 구성 절차와 도구는 `.agents/skills/pleos-drive-sim/`(SKILL.md, scripts/)에 있다.

```sh
adb -s emulator-5554 emu grpc 8554     # 부팅마다 한 번(마이크 주입·소리 녹음)
scripts/road-test.sh all               # cake coffee baby pet food, 결과는 build/road-test/<시나리오>/
scripts/road-test.sh -n baby           # 녹화 없이 하나만
```

| 시나리오 | 흐름(실제 신호) |
|---|---|
| `cake` | 경유지 빵집에 다가가면 FusedLocation 근접 알림으로 제안 → "응"(STT) → 정차·P·트렁크 → 출발 → 급제동 → 창업로 유턴 사전 안내 → 도착 요약 → 하차 알림 |
| `coffee` | 판교역 가는 길 드라이브스루를 지나며 제안 → "응 켜줘" → 신호 대기 후 급출발 → 도착 → 컵홀더 알림 |
| `baby` | "아기 태웠어" → 출발 → 신호 대기에서 "아기 자요" 시도 → 수면 중 급제동(음성 없이 기록) → 유턴 안내 → 도착 → 확인해야 닫히는 하차 확인 |
| `pet` | "강아지 태웠어" → 빠르게(brisk) 회전하며 급커브 → 61분 경과 휴식 안내 → 도착 |
| `food` | "치킨 실었어" → 차분하게(calm) 끝까지 → 흔들림 오탐 0회, 무사 운반 요약 |

## 화면 설계

와이어프레임 v0.1의 화면 구성(G1–G6, F1–F7, A1–A3)을 따르고, 차량 화면이라 다음 원칙을 함께 지킨다.

- **주행 중엔 소리로, 멈추면 화면으로.** 주행 중 화면에는 켜진 모드 아이콘, 상태 한 줄("파손주의 물건 운반 중"), 보조 한 줄("민감도 최고 · 커브 300m 전 안내"), 큰 버튼 하나(말하기, 수면 중에는 수면 모드 끄기). Full 창에서는 "주행 중에는 간단히 보여 드려요"를 덧붙인다. 경고는 화면을 바꾸지 않고 TTS·효과음으로만 한다.
- **기능 이름 + 무엇을 하는지.** 모드는 이름 아래에 어떤 짐·동승자일 때 쓰는지(케이크·화분·와인)를 둔다. 정차 중 Grid는 켜진 모드가 있으면 그 모드가 하는 일(민감도·커브 안내·공조·도착 알림)을 표로 보여 준다(G4).
- **설정 문구는 Pleos 차량 설정 톤.** 스위치에는 늘 설명(`~합니다`)을 붙인다. 페이지 머리 설명은 아래 내용이 말해 주지 않는 것(운반 기록의 저장 위치, 픽업 장소 스위치의 뜻)에만 둔다. 선택지(Tabs)는 이름만으로 무엇을 정하는지 알기 어려울 때만 설명을 붙인다(민감도·커브 사전 안내·휴식 안내). 음성·팝업·안내는 `~해요` 체.
- **강조색은 하나.** Pleos Grayscale 토큰 위에 `informative_positive`(#0064FF, 다크 #0082FF) 하나만 켜진 모드와 주 동작에 쓴다. 설정 스위치는 회색. 모드별 색은 쓰지 않는다.
- **큰 표적.** 타일·행 112dp 이상, 버튼 96/128dp, 슬라이더 대신 Tabs, 픽업 장소는 검색·지도 대신 "지금 위치를 픽업 장소로 저장" 후 짐 종류만 고른다.

| 상태 | Grid(세로 창) | Full(가로 창) |
|---|---|---|
| 주행 중 | G1 켜진 모드 + 상태 한 줄 + 말하기 / G5 수면 | F5 같은 화면 + 안내 한 줄 |
| 정차 중 | G3 모드 선택(모드 5개 + 말하기) → G4 활성화된 모드 | 좌측 레일: F1 홈 · F2/F7 모드 설정 · 운반 기록 · F4 픽업 장소 · F6 챌린지 |
| 이벤트 | G2 모드 제안, F3 운반 요약, A1 하차 알림(popup), G6 수면 중 이벤트 | 같은 화면 |

## 프로젝트 구조

```
app/src/main/java/dev/seungmin/goi/
├── care/    모드·공조 항목 정의, 공통 센서 엔진, 쏠림 판정, 챌린지, 음성 명령 파서
├── car/     Pleos SDK 연동(Vehicle·HVAC, NaviHelper TBT, FusedLocation 근접 알림)
├── voice/   TextToSpeech·SpeechToText(온디바이스, ko-KR)
├── data/    모드 설정·픽업 장소·운반 기록 저장
└── ui/      Compose 화면과 테마 토큰
app/src/debug/   에뮬레이터 데모용 adb 브로드캐스트 주입기(release에는 들어가지 않는다)
branding/        워드마크 SVG와 생성기
scripts/         drive-sim.sh, road-test.sh
apk/             제출용 release APK
```

## 검증 기록

- 에뮬레이터에서 확인: Vehicle SDK로 기어·브레이크·조향각·운전석 문·트렁크 수신, AAOS 차속 수신, 온디바이스 TTS(ko-KR) 발화, 공조 capability 조회.
- `distractionOptimized` 선언으로 차가 P를 벗어나도 Pleos 주행 규제 화면("주행 중에는 사용할 수 없습니다.") 대신 고이 화면이 보인다(에뮬레이터 `user` 빌드, adb 설치본). 달릴 때는 주행 중 화면(G1·G5·G6), 신호 대기(D, 0 km/h)에는 정차 화면이 나오고 말하기 버튼도 누를 수 있다.
- 2026-11-06 모의주행 `road-test.sh -n cake`: 픽업 장소 근접 제안, "응" STT, 파손주의 모드 켜짐, 급제동 감지·음성 안내, 도착 요약은 PASS. 창업로 유턴 사전 안내와 트렁크 하차 알림은 FAIL(트렁크 열림 이벤트는 앱에 들어왔으나 도착 때 "파손주의 물건을 챙기세요"가 나옴). 2026-11-05 `baby` 리허설에서도 유턴 사전 안내는 잡히지 않았다. 두 기능은 `drive-sim.sh`(앱 안 주입)에서는 동작한다.
- 단위 테스트: `./gradlew testDebugUnitTest` 20개(쏠림 판정, 음성 명령, 모드 합치기, 하차 문구, 챌린지, 운반 요약 제목).

## 제약과 대안

- 에뮬레이터 공조 전원이 꺼져 있으면 HVAC 쓰기가 `PropertyNotAvailable`로 실패하고, 앱은 음성 권유로 대신한다. Virtual Console에서 HVAC Power를 켜면 적용된다.
- Light SDK에는 앰비언트 색 제어 API가 없어(실내등 on/off만 제공) 기획서의 앰비언트 색상 기능은 넣지 않았다.
- TTS SDK에 음량 API가 없어 수면 모드의 "안내 음성 작게"는 짧은 문장으로 대신한다.
- 뒷좌석 별도 온도 영역이 없는 차에서는 운전석 영역 온도를 맞춘다.
- 운반 요약의 도착지 이름(예: "→ 집")은 내비 목적지를 읽지 않아 표시하지 않는다. 출발 장소는 픽업 장소 제안으로 모드를 켰을 때만 보인다.
- 주행 규제는 신호 대기도 DO 대상(`idling`, 설정 화면 제한 `NO_SETUP`)으로 본다. 공모전 시연을 위해 신호 대기에는 정차 화면을 그대로 두었으며, 출시하려면 이때도 주행 중 화면을 띄워야 한다.
- 에뮬레이터 마이크로 넣은 "아기 자요"는 다른 말로 인식될 때가 많다(5번 중 1번 인식, "아기 자연" 등). `scripts/road-test.sh`는 못 알아들으면 디버그 주입으로 이어 간다.
- 챌린지는 모드별 5개를 운반 기록으로 계산한다. 외부 공유·인증 배지는 넣지 않았다.
- release APK는 지금 debug 키로 서명한다.
